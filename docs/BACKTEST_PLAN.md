## 1. 목적 — 이 하니스가 답해야 하는 질문

1. **정합성**: 현행 레지스트리(0.2.0)가 역사적 분기점 9창(양성 7·음성 2)에서 설계 의도대로 발화·승격·강등하는가.
2. **보정**: D-12(usdkrw 양방향 임계), F-04(구조지표 가중·임계 — 골든 희석 없이 활성 가능한 조합), `mobile_daily` 프로파일 파라미터의 1차 최적값은 무엇인가.
3. **성능**: 리드타임·오탐·플래핑·해상도(F-06)를 수치로 — 그리고 그 수치가 수용 기준을 넘는가.
4. **동등성**: Kotlin 엔진이 Python 참조 엔진과 동일하게 계산하는가(BT-05).

## 2. 구성 요소

```
engine_ref/            # 순수 함수 참조 엔진: transforms · severity · modifiers · composite(D-02) · statemachine(프로파일 주입)
backtest/
├── fixtures/          # 창별 Parquet (build_fixtures.py가 yfinance/FRED/pykrx 소급 수집으로 생성, as-of 정렬)
├── golden_server.yaml # D-08 기대값 (server_intraday) — 기존 2케이스 이관
├── golden_mobile.yaml # BT-02 산출 (mobile_daily 기대값)
├── run_replay.py      # 창×설정×프로파일 리플레이 → metrics.json
├── run_sweep.py       # 보정 스윕 (그리드 정의는 sweep.yaml, 코드 하드코딩 금지)
└── report.py          # BT_REPORT.md + 차트 생성
```

원칙: 엔진 로직은 `engine_ref` 한 곳에만 존재한다. 서버 detection(S1)과 하니스가 같은 코드를 import하고, Kotlin은 패리티 테스트로 동결 일치를 증명한다. 하니스에 임계·가중치 리터럴 금지(SSOT 규율 동일 적용).

## 4. 서브태스크

### BT-01 픽스처·참조 엔진
`build_fixtures.py`로 9창 수집(레이트리밋 K-03, 항목당 캐시), engine_ref 이식(기존 P0 명세 D-01~D-03 + D-12 그대로).
완료: 픽스처 스키마 검증 테스트 + engine_ref 단위 테스트(경계값·결측 분모 제외·modifier) green.

### BT-02 골든 이관·확장
server_intraday로 기존 골든 2케이스 재현(30분 틱 근사는 기존 방식 유지) + mobile_daily로 일봉 리플레이해 기대 타임라인 산출 → `golden_mobile.yaml` 확정. 2026-07 창의 두 프로파일 결과를 D-14 상신 자료로 정리.
완료: `pytest backtest/test_golden.py` — 2케이스 × 2프로파일 green.

### BT-03 보정 스윕 (핵심)
스윕 대상(sweep.yaml): ① usdkrw 양방향 임계(D-12) ② F-04 2종 {weight × thresholds} — **골든 무회귀를 하드 제약**으로 활성 가능 조합 탐색(희석 문제의 해가 없으면 "비활성 유지"가 결론) ③ mobile_daily {promote_sustain, demote_below, min_dwell, 확정 틱 시각 16:20 vs 17:00} ④ 스테일 창.
선정 규칙(고정): 홀드아웃 제외 7창에서 수용 기준(§6) 통과 조합 중 오탐 최소 → 리드타임 최대 순. 동률이면 단순한 값.
완료: `BT_REPORT.md`에 스윕 표 + 선정 근거, `configs/*` 0.3.0-rc 반영(스키마 검증 green).

### BT-04 성능·해상도 리포트
0.3.0-rc로 9창 전체 재실행: §6 지표 산출 + F-06 해상도 분석(severity 3 고정 지표 수 시계열, composite 최고치). 해상도 손실 확인 시 대응안 3종(임계 사다리 확장 / severity 4단계 / RED 서브레벨)을 **동일 하니스로 비교 시뮬레이션**해 제안서 작성 — 채택은 사용자 승인 후 별도 반영(임의 구현 금지).
완료: `BT_REPORT.md` 완성 + GM0 게이트 리포트에 요약 편입.

### BT-05 Kotlin 패리티 (M1 소속)
동일 픽스처(일봉)를 앱 계측 테스트에 주입: |Δcomposite| ≤ 0.05(전 틱), 국면 타임라인 완전 일치, 골든 mobile 기대값 일치.
완료: `./gradlew connectedCheck`(또는 로컬 JVM 테스트 타깃) green — GM1 조건.

## 5. 한계 관리 (정직성 조항)

1. 소급 수집치는 개정치 포함 가능 → 진짜 PIT 아님. 모든 산출물 머리에 "근사-PIT" 명기, C1에서 실측 lake로 재확정.
2. 30분 틱 재현은 2024-08 골든 외 창에서 일봉 근사 — server 프로파일의 정밀 검증도 C1 몫.
3. 스윕은 9창 표본의 보정이다. "모든 임계값은 가설"(D-04) 규율이 0.3.0에도 그대로 적용된다.
