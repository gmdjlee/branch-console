## Round 3 — C-05 판정 철회 (사용자 지적, 2026-08-02)

- **사실**: `claude-opus-5`·`claude-sonnet-5`는 공식 문서·API에 실재하는 현행 모델 ID다. Claude Code에서도 사용 가능하다.
- **오류의 성격**: Round 1의 C-05는 "문서에서 확인되지 않음"이라고 썼지만, 실제로는 **확인 절차 없이 기억으로 판정**했다.
  즉 C-05가 지적한 죄목("근거 없는 ID 승계")을 판정자 본인이 저질렀다. 낡은 정보로 최신 정보를 반려한 전형적 오류다.
- **조치**: D-20을 전면 재작성해 ID를 확정 채택하고, 런타임 티어링(§20.1) + 개발 시 Advisor/Worker 배정(§20.2) +
  분기 재검증(§20.3)으로 확장. statemachine 패치의 placeholder 제거, `.claude/agents/*` 전체 ID 고정,
  `CLAUDE_CODE_SUBAGENT_MODEL` 미설정 규칙 추가. MT0-01은 "선택 실측"에서 "확정값 적용 + 스모크 검증"으로 축소.
- **교훈(프로세스 반영)**: 비평은 근거 조회를 동반해야 한다. aaa-critic 규칙의 "판정 전에 산출물을 실제로 열어 재현하라"를
  외부 사실 주장에도 적용한다 — 문서·API·실행 결과로 확인되지 않은 반려는 그 자체가 결함이다.

## Round 4 — 기능 동등성 검증 (사용자 요청, 2026-08-02)

질문: "모바일이 상시 가동을 제외하고 서버와 동일한 기능을 하는가."
검증 방법: 서버 phase 산출물(S1 ST-01~10 / S2 ST-P2-01~07 / AL-01~05 / S3 ST-P3-01~06)과
모바일 MT1·MT2 서브태스크를 계층별로 대조.

- **판정: 아니다.** 파이프라인(수집→원장→엔진→상태기계→evidence→LLM→알림)은 동등하나,
  **판단의 근거 재료 3종(analogue·뉴스 축·HMM)이 서버 전용**이며 수집 지표 1종(kr_cds_5y_delta)에 모바일 경로가 없다.
- 문서상 문제: D-15 표가 뉴스 축만 언급하고 analogue 부재는 MT2-01의 괄호 서술에 묻혀 있었다.
  가장 큰 격차(G-1)가 가장 눈에 안 띄는 위치에 있던 셈이다.
- 조치: **D-22 기능 동등성 매트릭스 신설**(G-1~G-5), MT1-04f(CDS 판정)·MT2-01(시드 인용 완화)·MT2-06(고지 확대) 반영.
- 남는 판단: G-1의 시드 인용은 임베딩 검색의 대체재가 아니다. 진폭 추정 품질은 AL 완료 후 INT에서 재평가한다.

## Round 5 — 온디맨드 분석 동등성 검증 (사용자 요청, 2026-08-02)

질문: "모바일에서 사용자가 분석을 지시하면 서버와 동일한 결과가 나오는가."

- **판정: 아니다.** 3층위(설계상 차이 / 입력 차이 / LLM 비결정성)로 분해해 D-23에 기록.
- **신규 결함 발견 (심각)**: `missing_data_policy: exclude_from_denominator`(D-02)와 장중 KRX 조회 불가가 결합하면
  프리뷰 composite가 **방향성 오류**를 낸다. 국내 지표(가중 8.5)가 분모에서 빠져 "국내가 잠잠하다"는 정보가 소실되고,
  글로벌만 발화한 국면에서 66.7(RED 조건) vs 서버 45.2(ORANGE)로 한 단계 과대평가된다. 역방향 과소평가도 성립.
  → D-23 §23.3 규율(carry-forward + coverage 표기 + 80% 미만 판정 억제 + 확정 틱 예외 금지)로 처리, MT1-07 완료 기준에 재현 테스트 추가.
- **부수 정정**: D-22의 지표 총가중을 29.5 → **31.0**으로 정정(합산 오류). G-4 비중은 4.8%.
- 추가: 리포트 버튼을 확정 스냅샷에서만 활성(§23.3-5), INT 게이트에 확정 국면 일치율 ≥90% 조건 신설(§23.5).
- 교훈: "엔진 패리티 통과"는 동등성의 증명이 아니다. 패리티는 *입력이 같을 때*만 말해주며, 실제 격차는 수집 계층의
  가용성 차이에서 발생한다. 이후 동등성 주장은 반드시 입력 커버리지와 함께 진술한다.

## 잔여 리스크 (계획으로 해소 불가, 실행 단계 이관)

1. mobile_daily 프로파일 값 전부 가설 — BT-03 결과 전에는 어떤 문서 수치도 확정으로 읽지 말 것(D-04).
2. 근사-PIT 한계(BACKTEST_PLAN §5) — GM0 수치는 C1 실측으로 재확정된다.
3. 야후계 엔드포인트·KIS 정책은 실측 전 미확정(MT1-04a data-verifier 선행이 게이트).
4. 모델 세대 교체(폐기 일정)는 분기 C-주기 실조회로만 추적한다 — 문서에 적힌 ID를 근거로 삼지 않는다(Round 3 교훈).
5. 모바일 v1의 시나리오 리포트 진폭 추정은 analogue 근거가 축소된 상태다(G-1). 사용자 고지와 INT 해소가 전제다.
6. mobile_daily carry-forward 임계(coverage 80%)는 가설이다. BT-03 스윕에 커버리지 민감도 항목을 추가해 보정한다.
