# MT1-08 수동 E2E 체크리스트

이 문서는 MT1-08(노티 3채널 · 기능판 홈 · 자격증명 온보딩 · dailyCollect 배선)의 기능이
실기기/에뮬레이터에서 실제로 동작하는지 개발자가 손으로 확인하는 절차다.

**이 문서가 아닌 것**: GM1 게이트 증빙 절차서(`docs/runbooks/M1_SMOKE.md`, MT1-08c 소관 — 별도
서브태스크, 06 재판정 PASS 후 작성)와는 목적이 다르다. 이 문서는 08a/08b/08c(자격증명·온보딩·
dailyCollect 부분)/08d 구현 직후 개발자 본인이 회귀를 잡기 위한 체크리스트이고, 그쪽은 GM1
사용자 승인을 위한 공식 증빙 수집 절차다.

## 0. 준비

- [ ] 디버그 APK 설치(`./gradlew installDebug` 또는 Android Studio Run).
- [ ] KRX/FRED 자격증명 준비(실계정) — 없으면 3장(자격증명)은 "빈 값 검증" 경로만 확인.

## 1. 알림 채널 3종 (MT1-08a)

- [ ] 앱 최초 실행 후 시스템 설정 > 앱 > branch-console > 알림에서 채널 3개가 보이는지 확인:
      `국면 전이`(중요도 높음) / `잠정 경보`(중요도 기본) / `틱 실패 · 데이터 문제`(중요도 낮음).
- [ ] 채널 하나(예: 잠정 경보)를 꺼본 뒤 앱을 재시작 — 채널이 다시 켜지지 않고 사용자 설정이
      유지되는지 확인(D §3.9.1의 "재생성 시 사용자 설정 복원" 플랫폼 제약과 일치해야 정상).

## 2. 알림 권한 (K-20)

- [ ] 최초 실행 시 알림 권한을 거부 — 홈 화면에 "알림이 꺼져 있습니다" 배너가 상시 노출되는지
      확인(앱이 죽거나 다른 기능이 막히지 않아야 한다).
- [ ] 설정 탭에서 [알림 권한 요청] 버튼으로 다시 허용 — 배너가 사라지고 설정 탭의
      "알림 권한: 허용됨" 표시로 바뀌는지 확인.

## 3. 국면 전이 노티 (phase_transition)

- [ ] (사전 조건: 확정 틱이 최소 1회 커밋된 상태) 국면이 바뀌지 않는 이틀은 알림이 오지
      않아야 한다.
- [ ] 국면이 바뀌는 확정 틱이 커밋되면 그 확정 틱 완료 직후(`ProductionConfirmTickWorker.doWork`가
      `super.doWork()` 직후 바로 확인 — 별도 폴링 지연 없음) "국면 전이" 채널로 알림이 오는지 확인.
      문구가 `이전국면 -> 이후국면 · 날짜` 형태인지 확인.
- [ ] 같은 상태를 다시 확인해도(앱 재실행 등) 같은 전이로 중복 알림이 오지 않는지 확인.

## 4. 틱 실패 노티 (tick_failure)

- [ ] 비행기 모드 등으로 확정 틱을 의도적으로 실패시킨다.
- [ ] "확정 틱 실패" 채널로 알림 1건이 오는지 확인.
- [ ] 같은 날 다시 실패를 유발해도 두 번째 알림은 오지 않는지 확인(1일 1건 예산).
- [ ] 다음 날 다시 실패하면 알림이 다시 오는지 확인(예산 리셋).
- [ ] 실행 이력(이력 탭)에 `failed` 항목과 사유가 남아 있는지 확인.

## 5. 프리뷰 갱신 · 잠정 경보 (provisional_alert)

- [ ] 홈 탭 [프리뷰 갱신] 버튼을 탭 — 성공 시 `PREVIEW · composite ... · coverage ...`가 표시,
      실패 시(현재 SSOT에 `confirm_time_kst` 미기입 상태라면 실패가 정상) "프리뷰 실패: ..."
      인라인 메시지가 뜨고 앱이 죽지 않는지 확인.
- [ ] `confirm_time_kst`가 SSOT에 채워진 이후: coverage가 임계 미만이면 "국면 판정 불가"
      문구와 함께 잠정 경보가 **오지 않는지**(억제) 확인.
- [ ] 지표 중 하나가 crit 수준이고 억제되지 않은 상태에서 "잠정 경보" 채널로 알림이 오는지 확인.
- [ ] 같은 날짜(as_of)를 두 번째로 갱신했을 때 값이 최신으로 반영되는지(조용히 무시되지
      않는지) 확인 — 두 번째 탭이 첫 번째 탭과 다른 결과를 보여줘야 정상.

## 6. 홈 화면 상태 7종 (MT1-08b)

실기기에서 인위적으로 만들기 어려운 상태(GAP·WARMUP 등)는 JVM 테스트
(`HomeStateMapperTest`, `--tests "*HomeState*"`)가 전건을 담당한다 — 아래는 실기기에서
합리적으로 재현 가능한 것만 확인한다.

- [ ] **EMPTY**: 최초 설치 직후 홈 탭 — "최초 실행 대기" 배너.
- [ ] **NORMAL**: 확정 틱 1회 이상 커밋 후 결측 없이 정상 — 배너 없음, 국면·composite·상위
      지표 표시.
- [ ] **ERROR**: 4장 방식으로 확정 틱 실패 유발 — "오류" 배너.
- [ ] **PARTIAL**: 야후/FRED 중 하나를 비행기 모드로 결측시키고 확정 틱 통과 — "부분 결측"
      배너 + coverage < 100%.
- [ ] **SUPPRESSED**: 프리뷰 coverage가 임계 미만인 상태에서 홈 재진입 — "국면 판정 불가
      (참고용)" 배너.

## 7. 자격증명 온보딩 (MT1-08c/08d, K-17)

- [ ] 설정 탭에서 KRX ID/PW, FRED 키 입력 후 [저장] — 앱을 완전 종료 후 재실행해도 값이
      유지되는지 확인(암호화 저장 왕복).
- [ ] [KRX 검증] / [FRED 검증] 버튼 — 올바른 값이면 "확인됨", 틀린 값이면 "실패: ..."가
      즉시 표시되는지 확인(1회 소량 실호출).
- [ ] `adb shell run-as com.branchconsole.app cat shared_prefs/branch_console_credentials.xml`로
      저장 파일을 열어 값이 평문으로 보이지 않는지 확인(암호문이어야 한다).
- [ ] `adb logcat`을 켜둔 채 저장·검증을 수행한 뒤 로그에 입력한 키/비밀번호 문자열이
      그대로 노출되지 않는지 grep으로 확인.
- [ ] 절전 예외 안내: 배터리 최적화가 켜진 상태에서 설정 탭 진입 — 제조사별 안내 문구
      (삼성 vs 기타)와 [배터리 설정 열기] 버튼이 실제로 시스템 설정을 여는지 확인.

## 8. dailyCollect 배선 (MT1-08c/08d, aaa F-3 해소 확인)

- [ ] 자격증명 미설정 상태로 앱을 처음 설치·실행 — 시간이 지나 확정 틱 워커가 돌면 이력
      탭에 `not_configured` 항목이 남는지 확인(크래시 없이 무해 종료).
- [ ] 자격증명 설정 후 하루 이상 앱을 방치(또는 캐치업 트리거) — 이력 탭에 `not_configured`
      가 아닌 정상/실패 항목으로 바뀌는지, 홈 탭의 "확정 coverage"가 갱신되는지 확인.
- [ ] (선택, 실기기 로그 확인 가능 시) dailyCollect가 KRX/야후/FRED 3개 수집기를 순서대로
      호출하는지 `adb logcat`에서 KrxRateLimiter 등의 로그로 간접 확인.
